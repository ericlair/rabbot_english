DB 구조

만든 테이블 5개 완료
  • users · 사용자 (비밀번호는 해시만 저장)
  • writing_prompts · AI가 낸 주제와 빈칸 양식
  • writings · 작문과 교정본
  • corrections · 틀린 표현 한 건씩
  • api_usage · 하루 호출 횟수
설계만 있는 테이블 예정
  • chat_sessions, chat_messages · 대화 연습 기록
  • translations · 번역 기록
틀린 표현을 한 건씩 저장해서 나중에 복습에 쓸 수 있는 구조

다음 프로젝트: 컴퓨팅 자원 경매 예정

아이디어
  • 서버 자원(CPU·메모리)을 시간 단위로 나눔
  • 여러 사용자가 입찰해서 배분
  • 낙찰되면 해당 시간 동안 자원을 할당
방식
  • 실제 서버를 파는 게 아니라 시뮬레이션
  • Docker 컨테이너의 자원 제한으로 시연
  • 학습·포트폴리오 목적 (가칭 ComputeBid)
자원은 부족하다는데 배정된 자원은 놀고 있다는 문제의식에서 시작

흐름과 핵심

1단계입찰

시간 슬롯을 등록하고 여러 사용자가 동시에 가격 제시

→
2단계낙찰

마감 시 최고가를 결정

→
3단계할당·정산

컨테이너에 자원을 할당하고 정산 기록

핵심
  • 단순 CRUD가 아니라 동시성과 정합성이 중심
  • 동시에 입찰이 들어와도 최고가와 잔액이 맞아야 함
먼저 할 것
  • 입찰부터 정산까지 끝까지 도는 한 줄 완성
  • 그 뒤에 기능을 하나씩 확장

일반 경매와 다른 점

시간 슬롯
  • "이 물건"이 아니라 "이 시간대의 자원"을 거래
분할·묶음 입찰
  • 코어·메모리 단위로 쪼개고, 여러 자원을 묶어서 입찰
선점·회수
  • 더 높은 입찰이 낮은 입찰의 자원을 중단시킴
사용량 정산
  • 낙찰로 끝나지 않고 실제 사용을 측정해 정산
  • 안 쓰는 자원은 회수해 다시 경매
한 번 팔리고 끝나는 경매가 아니라, 시간과 사용량이 붙는 경매

만드는 범위

필수 기능 (MVP)
  • 슬롯 등록·조회, 가상 포인트
  • 동시 입찰과 최고가 갱신
  • 마감 시 낙찰자 결정
  • 낙찰 시 Docker 컨테이너 생성
  • 종료 후 정산, 원장 기록
확장 (선택, 우선순위 순)
  • 선점·회수
  • 경매와 고정가 방식 비교 실험
  • AI 가격 추천 (계산은 규칙·DB가 담당)
필수 기능을 끝까지 먼저 돌리고, 확장은 순서대로 진행
